# Task 0.2 — فهم .gitignore

## Preview

هذا الملف يحدد الملفات المحلية التي لا نريد إضافتها إلى Git: الأسرار، المكتبات المنزّلة، والملفات الناتجة من التشغيل والبناء. مكانه في جذر المستودع حتى يغطي backend وfrontend. هو إعداد للمستودع، وليس جزءًا من مسار HTTP داخل Laravel.

الملف كان موجودًا. عدّلنا قواعد storage حتى نستبعد محتويات التشغيل ونسمح بملفات .gitignore التي تحفظ بنية المجلدات. Git يتتبع الملفات ولا يتتبع المجلدات الفارغة.

## كيف تقرأ القواعد؟

- السطر الذي يبدأ بـ # تعليق؛ والسطر الفارغ يفصل الأقسام.
- * يطابق أسماء متعددة داخل مستوى المسار.
- ! يستثني ملفًا من قاعدة تجاهل سابقة؛ ترتيب القواعد مهم.
- الاسم دون / مثل .env يطابق هذا الاسم في مستويات مختلفة.
- vendor/ يطابق مجلدات بهذا الاسم، بما فيها backend/vendor.
- تجاهل المجلد نفسه يمنع إعادة تضمين ملف داخله؛ لذلك نستخدم directory/* ثم الاستثناء.

## Walkthrough — كل قاعدة بالترتيب

هذه المهمة تطبق قاعدة blueprint §8.1 الخاصة بالأسرار ونظافة المستودع. لا تحتاج تطبيق مبدأ SOLID: هذه مبادئ لتصميم الكود، ولا يجب فرضها على ملف إعداد Git.

## Verification

نختبر القواعد بأداة Git نفسها عبر git check-ignore --no-index. تحققنا بنسخة مؤقتة من الملف لأن المستودع الأصلي يعرض خطأ ملكية. هذا يؤكد سلوك القواعد، لكنه لا يثبت أن المستودع الأصلي خالٍ من ملفات حساسة متتبعة مسبقًا.

يجب تجاهل .env وbackend/.env والمكتبات والسجلات والكاش، والسماح بـ backend/.env.example وملفات حفظ المجلدات والكود وcomposer.lock وpackage-lock.json.

تنبيه عملي: .gitignore لا يزيل ملفًا متتبعًا مسبقًا ولا يمحو Git history. إذا تسرّب سر، تدويره مطلوب؛ إضافة قاعدة تجاهل وحدها لا تكفي.

## Developer review

اقرأ الملف والجدول، ثم اذكر أي قاعدة غير واضحة. نراجعها قبل أسئلة المقابلة.

## Recruiter round — أجب بكلماتك

1. لماذا نرفع .env.example ولا نرفع .env؟ وما نوع القيم المسموح وضعها في النموذج؟
2. لماذا لا نرفع vendor وnode_modules، لكن نرفع composer.lock وpackage-lock.json؟
3. ما الفرق بين تجاهل storage/logs/ وتجاهل storage/logs/* مع استثناء .gitignore؟
4. إذا كان .env متتبعًا سابقًا، هل إضافة اسمه إلى .gitignore تحمي السر؟ ماذا تفعل؟

Read .gitignore first, this walkthrough second, then the tracker. There is no HTTP flow: Git reads exclusion rules when deciding whether untracked files should be offered for staging.

## Good and bad examples

Teaching-only flawed configuration:

```gitignore
backend/storage/logs/
!backend/storage/logs/.gitignore
```

The excluded parent directory prevents re-including its file. The chosen implementation excludes the contents instead:

```gitignore
backend/storage/logs/*
!backend/storage/logs/.gitignore
```

The trailing wildcard allows the later exception to work. This preserves a directory placeholder while keeping generated logs local.
