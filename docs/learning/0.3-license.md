## Good and bad approaches

Good: keep a standard LICENSE document tracked at the repository root, so readers can find it. Why: the blueprint explicitly calls for a license, and standard wording makes the chosen terms identifiable.

Teaching-only bad configuration:

```gitignore
LICENSE
```

If LICENSE is untracked, this rule keeps it out of ordinary staging and it may never reach the repository. Smallest fix: remove that rule and verify the file can be staged. For an already tracked LICENSE, an ignore rule does not stop tracking; file state matters.

Do not replace the standard license text with an informal sentence or add contradictory conditions. This task is about understanding the existing standard, not composing new legal terms.

## Independent review — attempt before asking for the answer

```gitignore

```

Assume LICENSE and backend/.env.example exist and are untracked. Trace each rule in order. Which files can ordinary staging include? Does the nested example exception behave as intended? Explain the edge case and propose a correction. Do not assume a leading ! always succeeds.
