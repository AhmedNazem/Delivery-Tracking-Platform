# 0.5 — حارس حجم ملفات الكود

## شنو بنينا؟

أضفنا 3 ملفات وعدّلنا ملفين: TASKS.md لتسجيل التقدم وBLUEPRINT.md لتثبيت طلب الشرح البسيط والأمثلة الواقعية:

1. [السكربت](../../scripts/check-file-length.sh): يفحص طول ملفات الكود.
2. [الاختبارات](../../tests/scripts/check-file-length-test.sh): تنشئ ملفات مؤقتة وتتأكد من نتيجة الفحص.
3. هذا الدليل: شرح وأمثلة وتدريب مراجعة.

اقرأ السكربت أولًا، ثم الاختبارات. ماكو Laravel أو HTTP هنا؛ هذا برنامج صغير نستخدمه محليًا، وبعدها داخل CI.

## مثال من الحياة

تخيّل موظف يستلم ملفات، وتعليماته: أي ملف بيه أكثر من 150 سطر شغل يرجعه لصاحبه حتى يقسّمه.

الموظف هو السكربت. قائمة الأماكن هي SCAN_ROOTS. الحد هو MAX_LINES. الاختبارات مثل مدير يعطي الموظف ملفات تجريبية ويتأكد أنه يطبق التعليمات صح.

## مسار التنفيذ

تشغّل السكربت → يحدد جذر المشروع → يبحث عن ملفات الكود → يستثني الملفات المولّدة → يعد أسطر الكود → يقارن بالحد → يطبع النتيجة.

```bash
bash scripts/check-file-length.sh
```

وتشغّل اختبار السلوك بهذا الأمر داخل Bash:

```bash
bash tests/scripts/check-file-length-test.sh
```

على Windows استخدم Git Bash؛ يحتاج أدوات find وawk وmktemp الموجودة مع Git Bash. PowerShell وحده لا ينفّذ صيغة Bash.

## قراءة السكربت ببساطة، بالترتيب

- `#!/usr/bin/env bash`: يحدد أن لغة الملف Bash.
- `set -euo pipefail`: يوقف أخطاء الأوامر والمتغيرات غير المعرفة، ويكشف فشل الأوامر داخل pipeline.
- `MAX_LINES=150`: الحد في مكان واحد، بدل نشر رقم 150 بكل الكود.
- `root=...`: يأخذ المسار الذي تمرره؛ وإلا يستخدم مجلد المشروع المحسوب من مكان السكربت.
- `cd -- "$root"`: يدخل مجلد المشروع. علامات الاقتباس تحفظ المسار إذا بيه مسافات؛ و`--` يفصل الخيارات عن المسار.
- `EXEMPT_PATHS`: قائمة مسارات معفاة صراحة. ملفات migrations والكاش والبناء خارج أماكن البحث أصلًا؛ وsrc/generated قد يكون داخلها، لذلك يحتاج استثناء.
- `SCAN_ROOTS`: أماكن البحث، سواء الكود في الجذر أو داخل backend/frontend.
- `failed=0`: بعدنا ما لقينا مخالفة.
- `checked=0`: عدد الملفات المفحوصة.
- `is_exempt()`: تقارن المسار بكل استثناء. `return 0` يعني وجدنا تطابق؛ `return 1` يعني لا يوجد تطابق.
- `local`: متغير يخص الدالة، مثل ورقة عمل داخل مكتب الموظف.
- `count_code_lines()`: تعطي مهمة قراءة الملف إلى awk، أداة تقرأ النص سطرًا سطرًا.
- `scan(line, ...)`: تفحص حروف سطر واحد؛ المتغيرات بعد line محلية لهذه الدالة في awk.
- `code`: هل هذا السطر يحتوي كودًا؟ نبدأ أيضًا بحالة وجود نص مفتوح من السطر السابق.
- حلقة `for`: تمر على الحروف واحدًا واحدًا.
- `c`: الحرف الحالي؛ `pair`: الحرف الحالي واللي بعده، حتى نميّز `//` و`/*` و`*/`.
- `block`: إحنا داخل تعليق طويل. نتجاهل الحروف لحد `*/`.
- `quote`: إحنا داخل نص بين علامات اقتباس. الرموز داخل النص لا تتحول إلى تعليقات.
- `\\`: حرف escape؛ نتجاوز الحرف التالي حتى علامة اقتباس مهربة ما تغلق النص بالخطأ.
- `//` و`#`: بداية تعليق إلى نهاية السطر، عندما نكون خارج النص.
- `/*`: يفتح تعليقًا طويلًا قد يمتد لعدة أسطر.
- `\042` و`\047`: تمثيل علامتي الاقتباس المزدوجة والمفردة، وbacktick للنصوص التي تستخدمه.
- فحص المسافة: إذا الحرف مو فراغ، نسجل وجود كود.
- `return code`: يرجع 1 لسطر كود، أو 0 لسطر فارغ/تعليق فقط.
- `count += scan($0)`: يضيف نتيجة السطر إلى المجموع؛ `$0` في awk يعني السطر كاملًا.
- `END`: يطبع العدد بعد نهاية الملف، وحتى الملف الفارغ يرجع صفرًا.
- `check_file()`: يستثني الملف إذا مطلوب، يحسب طوله، ثم يزيد عداد الملفات.
- `lines > MAX_LINES`: فقط الأكثر من 150 يفشل؛ 150 بالضبط مسموح.
- `printf ... >&2`: يطبع اسم الملف وعدده في قناة الأخطاء.
- `failed=1`: يسجل المخالفة، لكنه يكمل حتى يعرض بقية الملفات المخالفة.
- الحلقة الأخيرة: تمر على مجلدات البحث، وتتجاوز المجلد غير الموجود لأن المشروع بعده يتكوّن.
- `find`: يبحث عن ملفات PHP وJS وTS وShell فقط؛ Markdown مو كود تطبيق.
- `-print0` مع `read -d ''`: يفصل أسماء الملفات برمز خاص بدل الفراغ أو السطر الجديد. مثل ظرف مستقل لكل اسم؛ اسم `Long file.ts` ما ينقسم إلى اسمين.
- `< <(...)`: يمرر أسماء الملفات إلى الحلقة بدون جعل الحلقة عملية منفصلة؛ حتى قيمة failed تبقى متاحة بعدها.
- `exit 1`: نتيجة فشل تفهمها CI. مثل ضوء أحمر.
- آخر `printf`: نتيجة نجاح مع عدد الملفات. مثل ضوء أخضر.

## قراءة الاختبارات

- تحدد مكان السكربت انطلاقًا من مكان ملف الاختبار.
- `mktemp -d` ينشئ مجلد تجارب، منفصلًا عن ملفات المشروع.
- `trap` يحذف مجلد التجارب عند الخروج. المتغير يحمل فقط مسار المجلد الذي أنشأناه للتو.
- فحص وجود السكربت أعطانا أول نتيجة فشل قبل كتابة التنفيذ.
- `write_lines` تنشئ المجلد المطلوب وملفًا بعدد محدد من أسطر كود تجريبية.
- `expect_pass` تشغّل السكربت وتفشل الاختبار إذا رفض ملفًا مسموحًا.
- `expect_failure` تتأكد من exit 1 ومن وجود اسم الملف وعدده في الرسالة.
- الحالات بعدها تختبر مشروعًا فارغًا، ثم 150 و151 سطرًا، ثم مجلدات البحث وأسماء بمسافات.
- حلقة التعليقات تضيف أسطرًا فارغة وتعليقات؛ يجب أن يبقى ملف 150 سطر كود مسموحًا.
- سطر رابط داخل نص وسطر كود بعد تعليق يتأكدان أن كودًا حقيقيًا لا يضيع من العد.
- الملفات المعفاة وMarkdown لا تسبب فشلًا.
- مجلد جذر غير موجود يجب أن يفشل، بدل إعلان نجاح مضلل.
- آخر echo يعلن نجاح مجموعة الاختبارات كلها.

## ليش هذا الاختيار؟ ومتى ما يكفي؟

Bash مناسب لتشغيل أمر بسيط داخل CI، وawk متوفر عادة معه، بدون تثبيت مكتبات المشروع. كل دالة إلها وظيفة واضحة؛ هذا يساعد الفصل بين المسؤوليات، بدون إضافة طبقات Laravel إلى سكربت صغير.

هذا ماسح نصي، مو parser كامل لكل لغة. يدعم التعليقات المعتادة والنصوص بين الاقتباسات. صيغ مثل PHP heredoc وJS regex literals وPHP attributes وبعض تعبيرات template strings قد تحتاج دعمًا مخصصًا قبل استخدامها؛ التعليقات داخل هذه الصيغ قد تغيّر العد. النتيجة ليست إثباتًا لصحة PHP أو TypeScript.

ملفات scripts نفسها خارج نطاق الجذر المحدد بالـBlueprint؛ نفحصها يدويًا أيضًا. ملفات migrations وكاش bootstrap و.next خارج نطاق البحث، والاستثناء النشط داخل src هو generated. لا تضع كودًا يدويًا في generated للتهرب من الحد.

## نسخة سيئة ونسخة أفضل

نسخة تعليمية سيئة:

```bash
lines=$(wc -l < "$path")
```

تعد التعليقات والفراغات أيضًا، وقد ترفض ملفًا بيه 100 سطر كود و100 سطر تعليق. كذلك wc -l يعد فواصل الأسطر، وقد يفوّت آخر سطر إذا ما ينتهي بفاصل.

اختيارنا:

```bash
lines=$(count_code_lines "$path")
```

يعزل مسؤولية العد، ويتعامل مع التعليقات والفراغات والنصوص المدعومة. المقابل أنه أعقد من wc، لذلك يحتاج اختبارات وحدود واضحة.

## تمرين مراجعة — لا تشوف الحل قبل محاولتك

نتيجة الفحص: نجحت اختبارات الحدود، مجلدات البحث، المسافات، التعليقات، النصوص، الاستثناءات، والجذر غير الموجود. فحص المشروع الحالي نجح أيضًا؛ حاليًا الملف الوحيد داخل نطاق البحث هو ملف اختبار السكربت. فحص صيغة Bash نجح. لا يوجد CI بعد؛ سنضيفه في المهمة 0.6.

هذا المثال متعمد بيه خطأ، وغير مستخدم بالمشروع:

```bash
if ((lines >= MAX_LINES)); then
    exit 1
fi
```

## تمرين عملي وأسئلة مقابلة

اقترح اختبارًا لملف فارغ: شنو تتوقع يكون عدده؟ وشلون تعرف أن السكربت ما حسبه مخالفة؟ لا تحتاج تنفّذ قبل أن نشرح أي نقطة مو واضحة.

1. ليش نفصل عد الأسطر عن المقارنة بالحد؟
2. ليش الرابط داخل نص ما نعتبره تعليقًا؟ أعط مثالًا.
3. شنو يصير لو رجعنا نجاحًا رغم وجود ملف 151 سطرًا؟ شلون يأثر على CI؟
4. ليش استخدمنا طريقة تحفظ المسافات بأسماء الملفات؟
